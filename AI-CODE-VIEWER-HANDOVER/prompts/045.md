# Prompt 045 — Detect Python triple-quoted documentation

## Exact user prompt

> Some comments not picking up like 3 x " like that

## Clarified intent

Python triple quotes `"""` and `'''` (including multiline module/class/method documentation) should be recognized by the viewer's **Comments** selection, not just standalone `#` lines. Triple-quoted docstrings are technically Python string literals, not Python comment tokens, so this is explicitly a comment-like documentation **UI category**.

## Assistant outcome (summary; not verbatim)

Updated the actual `commit-id-demo/index.html` with a quote-state scanner over original physical source lines. It classifies standalone Python triple-quoted literal blocks and their interior lines, including the module header and method docstrings. In Comments mode the matching chips become pink; in the default Lines view and other hierarchy selections they remain green. Code assignments containing triple-quoted values stay code and do NOT receive pink chips. Rendering colors documentation text consistently. Original STM IDs/source text and sky-blue scope-start boundary rows remain unchanged.

## Future-AI rule

Do not rely solely on `^\s*#` to recognize Python documentation. Use language-aware parsing for complex source code; differentiate docstrings and standalone triple-quoted documentation from multiline string values assigned to variables or passed as arguments. A `#` inside a triple-quoted string is not automatically a standalone Python comment. Preserve historical blank-line STM IDs, hierarchy-colored blank chips, and the separate sky-blue synthetic boundary markers.
