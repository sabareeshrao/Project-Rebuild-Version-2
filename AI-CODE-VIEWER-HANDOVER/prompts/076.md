# Prompt 076 — Persistent Viewer State, Functional File Category and Independent Comments Toggle

## Original user message (verbatim)

> When i change optiojs like only added only and change the numer it is going back to full file inwant persistance state man everywhere and now make comments toggle button work along with file button too

The user attached a mobile browser screenshot of the restored dark original-history viewer at original commit #2. Its toolbar showed `Full file`, `Added only`, `Selected`, `All commits`, the file dropdown, the colored category row, and 630 original surviving source lines.

## Reproduced cause

The new `nanogpt-original-history/assets/app.js` previously reset viewing modes in **two event handlers**:
1. `selectCommit()` converted `All commits` to `Full file`.
2. A single-number Jump always forced `Full file`, and a range always forced `Selected`, regardless of an already selected `Added only` mode.

In addition, File and Comments buttons were disabled, and no category-toggle handlers were wired.

## Implemented and committed behavior

- **Modes are sticky** across Previous, Next and Jump: `Full file`, `Added only`, `Selected`, `All commits` remain selected until the user explicitly presses a different mode.
- Single-number Jump updates focused commit without modifying mode. Range Jump also preserves the selected mode: `Added only` shows only additions across the range; `Selected` shows real changed source lines; `Full file` shows surviving source at the range's ending commit; `All commits` keeps the complete timeline, automatically scrolling to the desired original commit.
- The File dropdown is a separate filter. It remains selected while switching modes or commits, including pressing `All commits`; select `All files` to clear explicitly.
- **File** category is now enabled, using the original saturated alternating sky-blue palette by actual source file. **Lines** is green. The source filename chip remains neutral gray and original code syntax coloring is untouched.
- **Comments** is an **independent toggle**. The user can have File+Comments or Lines+Comments pressed simultaneously. Python standalone comments and multiline triple-quoted documentation lines use pink STM chips; other code rows retain their selected File/Lines hierarchy colors. Deleted documentation is classified against the historical **pre-edit** snapshot and retains the pink/colored STM identity when struck through, while additions use the post-edit snapshot.
- Category toggle repaints existing virtualized DOM source rows in place, without rebuilding measured rows or resetting page scroll.
- Browser **localStorage** preserves mode, focused commit, selection range, file filter, selected category and Comments ON/OFF across reloads (when browser storage is allowed). Invalid/blocked storage does not stop the viewer.
- Every source identity, actual original Git patch, manifest, original 159-commit chronology, source text and the user's separate 235 teaching commits remain unchanged.
- Other category buttons (Class, Method, Block, Nested, Directory and Module) are still disabled, pending accurate structural classification.
