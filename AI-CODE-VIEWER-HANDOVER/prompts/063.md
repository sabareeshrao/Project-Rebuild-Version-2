# Prompt 063 — Remove Redundant Category Text from Colored Source Chips

## Original user message (verbatim)

> In chips why write all nonce when the color tells what its is dod you understood what i want?

The user attached a screenshot from the actual viewer, showing a **yellow** STM-046 chip with an extra visible first line similar to `NESTED · NBL-001 · if not self.flash`. The screenshot image itself was provided in ChatGPT and is **not claimed to be archived in this GitHub repository**.

## Assistant response — accurate summary, not a verbatim transcript

The assistant agreed that the chip's color already communicates its structural hierarchy category, so repeating `NESTED`, the nested-block ID and its source header as a visible label wastes space. It demonstrated a clean row with a neutral `model.py` filename chip, a yellow `STM-046` chip and the original `if not self.flash:` source to the right. It proposed removing the second chip-text line across **all categories**, retaining permanent STM and hierarchy metadata internally, and making rows more compact while preserving indentation, scrolling and filename-first order.

## Accepted / rejected changes

**New accepted rule:** the STM chip displays **only `STM-NNN`**. The chosen color alone identifies the category. This explicitly overrides the older first-chip-of-group rule that rendered `CLASS · CLS-001 · Name`, `NESTED · NBL-001 · Name` or `COMMIT N · +X` as visible chip text.

Keep the full `STM-NNN-FIL-NNN-filename` and scope IDs as underlying data/accessibility metadata; do not modify any historical source lines. No stacked nested boxes, redundant chip labels, removed code or synthetic rows.
