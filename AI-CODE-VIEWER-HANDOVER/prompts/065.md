## Original user message (verbatim)

> Give comment chip special power like if a category is selected and i want comment like toggle so that if i turn it on i can see comment color withon category

The user also attached a screenshot of the viewer's category controls, showing the existing Comments button. The original screenshot remains a conversation attachment; this file does **not** claim to reproduce or archive its pixels.

## Assistant response — implementation summary, not a verbatim chat transcript

Continued the accepted nanoGPT **modular viewer** on the latest 60-source-commit / 366-line baseline. The Comments category button is now an **independent ON/OFF overlay** rather than an exclusive category selection. Selecting Class + Comments simultaneously colors standalone comments and genuine docstrings **pink only inside that class**. All other class member lines retain Class red; comments outside all selected class scopes remain charcoal. The same rule applies to Method, Block, Nested, Lines, File, Directory and Module. Comments OFF restores the base category colors; changing the base category does not reset Comments.

Overlay changes use the existing in-place virtual row recoloring, preserving row object identity, measurements and natural page scroll. The filename-first neutral chip, single short STM visual label, full permanent STM ID, source code, category palette and conditional green code dividers remain unchanged. Scope/commit identifiers stay internal/accessibly exposed, not redundantly rendered in chip text.

## Accepted versus rejected behavior

**Accepted:** Base hierarchy and Comments may be active simultaneously. Toggle comments pink within matching colored member rows. Comments can be toggled off without changing hierarchy. Preserve the hierarchy filter when switching categories. Only comment/docstring source kinds qualify. New displayed controls retain stable dimensions and existing color fills.

**Rejected:** Comments as an exclusive mode; recoloring unrelated out-of-scope comments pink in a Class/Method/Block/Nested view; parsing inline `#` executable rows as standalone comments; changing source IDs/data; visually repeating structural/commit titles in STM chips; resetting virtual scroll or replacing rows.
