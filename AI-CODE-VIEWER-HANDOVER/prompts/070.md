## Interpretation for the proposed real-Git visualizer

- **Without deleted code:** 1,220 physical Python lines in the final snapshot, or 2,717 raw text lines including notebooks and documentation.
- **With deleted-code history:** 1,824 Python added-line occurrences throughout history, of which 604 correspond to line-deletion events; 3,783 raw text-line added occurrences including all text/notebooks, of which 1,066 deletion events exist.
- These are **line-change event counts**, not 1,824 uniquely different Python source texts: a line changed, removed and reintroduced may contribute multiple additions/deletions.
- Never show all struck-through deleted lines as if they remain part of an exact source snapshot. For the viewer, distinguish **historical diff** (struck-through deletions, preserved source-category colors) from **current code at that commit** (only surviving source). The mainline path and merge handling must be explicit.
- Binary images are excluded from line statistics. `.ipynb` figures count newline-separated raw JSON rather than executed source cells.

## Decisions and verification boundary

The user requested a count, not a new UI implementation. The existing modular nanoGPT viewer and 235 teaching commits were not modified. Counting was performed with GitHub REST endpoints plus exact current file content and verified arithmetically. It does not claim all 210 repository commits were Karpathy-authored; merge contributors exist. The proposed historical mode in [Prompt 069](069.md) remains **not implemented**.

The source-history count is a first-parent Git change-event tally; a truly unique-per-line lineage registry across moves/renames and repeat modifications would require a separate diff-tracking implementation. This record should not be misread as a completed lineage registry or a per-file deletion report.
